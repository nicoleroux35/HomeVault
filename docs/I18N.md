# Internationalization (i18n)

HomeVault ships in four locales: **English (`en`)**, **French (`fr`)**,
**Spanish (`es`)**, **German (`de`)**. The product UI defaults to French, but all
developer documentation is English.

## How it works

- Translation source of truth: `src/i18n/{en,fr,es,de}.toml` (TOML nested tables,
  flattened to dotted keys). The four files are at **key parity —
  2273 lines each** (`grep -cE '^[A-Za-z0-9_]+ *=' src/i18n/<lang>.toml`, as of
  2026-09-09), identical key sets, identical `%placeholder%` sets per key.
- The four `.toml` files are embedded into the binary at compile time via
  `include_str!` (`src/i18n.rs`, `load_embedded_translations`), so a bare copy of
  the binary needs no data files. At startup `init_i18n(None)` (`src/i18n.rs`)
  loads **only** that embedded content — no filesystem access at all. The
  optional disk overlay exists in `init_i18n(Some(path))` as a developer
  convenience (re-read `{locale}.toml` under `path`, winning on key collision),
  but nothing in the codebase passes `Some(..)`: every call site uses `None`.
  `embedded_translation_sources()` re-exposes the same bundles
  (`(locale, raw TOML)` pairs) so other subsystems can read translations from
  the binary alone — the RAG knowledge base's i18n indexer uses it instead of
  opening `src/i18n/*.toml`, which only exists in a source checkout.
- `I18n::translate` falls back to `en` for any missing key in the active locale,
  and finally returns the raw key if no translation exists (so missing strings are
  visible rather than empty).
- Variable substitution uses `%name%` placeholders, e.g.
  `snapshot.rollback_confirm` = `Rollback to snapshot "%name%"?` resolved via
  `t_with_vars("snapshot.rollback_confirm", &[("name", &snapshot.name)])`.
- The frontend also ships a small **embedded `translations` object** in
  `frontend/src/lib/stores/i18n.ts` (the pre-fetch fallback for the login/setup
  screens); it is kept correctly accented and is separate from the backend TOML.

## Frontend consumption

- The SPA loads the active map with `GET /translations`
  (`handle_get_translations` in `handlers/settings.rs`; the route is mounted at
  `/api/translations` in `src/web/mod.rs`, **not** `/api/settings/translations`).
- `frontend/src/lib/stores/i18n.ts` holds the map and exposes `t(key)`.
- `setLanguage(language)` (`POST /settings/language`) persists the choice and
  reloads the map. The Settings page has a language picker.

## Adding a string

1. Add the key under the correct `[section]` in `src/i18n/en.toml` (English is the
   base/fallback).
2. Add the same key in `fr.toml`, `es.toml`, `de.toml`.
3. Reference it in the component via `t('section.key')`.

Keys are grouped by feature: `nav.*`, `common.*`, `login.*`, `logout.*`,
`users.*` (incl. `users.home_size_*` — the home-directory size slider),
`groups.*`, `shares.*`, `storage.*` (also covers virtual-disk creation and
snapshots, e.g. `storage.snapshot_create` — see
[Snapshots](./guides/snapshots.md)), `dashboard.*`, `network.*`, `docker.*`,
`settings.*` (`settings.wallpaper_default` / `wallpaper_hint` — the
bundled-wallpaper picker), `health.*`, `explorer.*`, `raid.*`, `chat.*`,
`rag.*` (RAG knowledge base UI labels), `account.*`, `restic.*`, `terminal.*`,
`rclone.*`, `ups.*`, `snmp.*`, `notifications.*`, `search.*` (desktop command
palette — note `search.type_${type}` is a runtime lookup, so `search.type_app`
/ `type_action` / `type_setting` must never be pruned as "orphans").

### Accents

All four files were passed through a diacritics fix (2026-09-07 → 2026-09-08):
`fr` had whole sections written without accents ("Creer", "securite", …),
`de` used `ae/oe/ue/ss` digraphs, `es` was missing `-ción`/`¿?`. Values
only were touched — keys and `%placeholder%` tokens are byte-identical
across the fix. A native-speaker review of long-sentence verb tenses in
`es` is still the recommended follow-up.

> **2026-09-08 syntax fix:** `chat.rag_no_index` in `de.toml` contained an
> unescaped `"` mid-string (`… auf „Indexierung starten", um …`), which
> terminated the TOML basic string early and made the **entire German file
> fail `toml::from_str`** (`src/i18n.rs` logs a `warn!` and every `de` key
> silently falls back to English). Inner quotes escaped to `\"`. All four
> files now parse and are at exact key parity (run the parity check before
> shipping i18n changes).

> A previous top-level `[snapshot]` section (`snapshot.create`,
> `snapshot.rollback_confirm`, etc.) existed in all 4 locale files but was
> never referenced by any frontend code — dead keys, written ahead of an
> implementation that was never built. Removed when the real snapshot UI
> was added to `storage.*` instead, to avoid two parallel, inconsistent
> naming schemes for the same feature.

### Orphan-key removal & dynamic prefixes (2026-09-08)

**825 dead keys were removed** in one pass (3048 → 2223). A key is only
considered dead if neither its full dotted name nor its leaf is cited
anywhere in the Rust/Svelte source **and** it matches no dynamic prefix.
Some keys are built at runtime as `` `section.${var}` `` and must never be
deleted even though grep for the full name finds nothing — if you add a
new `` `section.${var}` `` lookup, keep the whole `section`. The known
dynamic prefixes:

- `docker.${actionKey}` and the 6 `docker.{container,stack}_{started,stopped,restarted}`
- `cache.mode_*`
- `desktop.{app,status,weather,calendar_weekday,launcher_cat}_*`
- `folder_picker.group_*`
- `ransomware.event_*`
- `rclone.job_status_*`
- `settings.update_*` and `settings.refresh_interval_*` (the interval labels,
  built by `settings.refresh_interval_${ms / 1000}s`) — both whole families
  must stay: the option list lives in
  `monitorStore.ts::REFRESH_INTERVAL_OPTIONS`
- `vpn.status_*`
- `journal.source_*`
- `downloader.status_*`
- `explorer.root_*`
- `search.type_*` (`search.type_${item.type}` in `SearchItem.svelte`)
- `vm.status_*`, `vm.w_size_*`, and `vm.os_*` (`vm.os_${id}` blurb lookup in
  `VirtualMachines.svelte`, id dots/dashes → underscores; falls back to the
  backend `OsOption.blurb` when the key is absent)

Also note: `handlers/settings.rs` makes ~12 **static** `I18n::t(...)`
calls from Rust — those keys are found by the normal name scan.

### Second pass — header-standardization orphans (2026-09-14)

The 2026-09-12/14 WindowHeader standardization (icon tile + title only, no
subtitle) orphaned **19 more keys**, removed from all four files in a second
pass — 2522 → **2503** keys each (`grep -cE '^[A-Za-z0-9_]+\s*='`, identical
in `en`/`fr`/`es`/`de`, placeholder sets identical, 0 mismatch):

`docker.containers_summary`, `users.summary`, `quotas.subtitle`,
`groups.summary`, `shares.summary`, `account.subtitle_admin`,
`account.subtitle_user`, `dashboard.overview_subtitle`, `rclone.subtitle`,
`raid.manager.header_subtitle`, `network.subtitle`, `chat.subtitle_default`,
`chat.model_via`, `vpn.subtitle`, `downloader.subtitle`,
`syncthing.subtitle`, `widgets.subtitle`, `rescue.subtitle`,
`journal.subtitle`.

The removal is **section-scoped**, which matters here: six *other* `subtitle`
keys were checked leaf-by-leaf and deliberately **kept** because they are still
live — `settings.subtitle` (the Settings rail label + nav aria-label),
`restic.subtitle` (`tabsLabel`), `login.subtitle` (the login page), and
`antivirus.subtitle` / `ransomware.subtitle` / `firewall.subtitle` (Settings
card subtitles). A bare `subtitle =` is never enough to identify a dead key.
`docker.${actionKey}` was re-checked: it only ever resolves to the six
`{container,stack}_{started,stopped,restarted}` keys, so removing
`docker.containers_summary` is safe.

## Notes / invariants

- Do **not** hardcode UI strings in components — use `t(...)`. Login, Setup
  Wizard, Users, Groups, Terminal, Account, Dashboard, RAID, Chat, Shares,
  Network and Backup/Restic were each audited specifically for missing
  translations; keep new strings covered in all four locales.
- `settings.translations` returns the flattened map (English base + active locale
  overrides), not the nested TOML.
- `CURRENT_LOCALE` (`src/i18n.rs:25`) defaults to `en` server-side; the SPA sends
  the user's chosen locale to `/translations` (mounted at `/api/translations`).
- `init_i18n(None)` is called once at startup from `run()`
  (`src/web/mod.rs:1170`).
- `embedded_translation_sources()` returns the same four embedded bundles as
  `(locale, raw TOML)` and is what the RAG i18n indexer consumes
  (`src/rag_indexers.rs::index_i18n`) — a subsystem reading those files off
  disk would index nothing on a deployed host, where `src/` never exists.
